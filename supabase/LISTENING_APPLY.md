# Applying the Cambridge Listening tests (Books 10–21)

48 tests, one continuous audio file each. Everything is generated by
`build_listening_seeds.py` and validated at build time (40 questions, every
answer present and — for choice types — in its options, no dirty instructions,
maps wired). Re-run the generator any time with `python build_listening_seeds.py`.

## 1. One-time storage setup (Supabase SQL editor)

```sql
-- Private buckets
INSERT INTO storage.buckets (id, name, public)
VALUES ('listening-audio','listening-audio',false),
       ('listening-images','listening-images',false)
ON CONFLICT (id) DO NOTHING;

-- Authenticated users may stream / read
CREATE POLICY "read listening audio"  ON storage.objects FOR SELECT
  TO authenticated USING (bucket_id = 'listening-audio');
CREATE POLICY "read listening images" ON storage.objects FOR SELECT
  TO authenticated USING (bucket_id = 'listening-images');
```

## 2. Upload the assets

| Bucket | Files | Path / name (exact) |
|--------|-------|---------------------|
| `listening-audio` | 48 merged MP3s | `Cambridge <N> Test <M>.mp3` |
| `listening-images` | 14 maps (in `supabase/listening-maps/`) | `Cambridge <N> Test <M> map.png` |

Names must match exactly — the seed references e.g. `Cambridge 16 Test 1.mp3`
and `Cambridge 16 Test 1 map.png`. Books/tests **with a map**: C11 T1/T2/T4,
C12 T4, C13 T1, C14 T2, C15 T2/T4, C16 T1/T4, C18 T2, C19 T1, C20 T3, C21 T2.

## 3. Insert the tests

The Supabase SQL editor caps query size, so the 48 tests are split into **6
parts**. In the SQL editor, open and **Run** each one in order:

```
supabase/cambridge-listening-part1.sql   (books 10 & 11) — also clears old listening
supabase/cambridge-listening-part2.sql   (books 12 & 13)
supabase/cambridge-listening-part3.sql   (books 14 & 15)
supabase/cambridge-listening-part4.sql   (books 16 & 17)
supabase/cambridge-listening-part5.sql   (books 18 & 19)
supabase/cambridge-listening-part6.sql   (books 20 & 21)
```

Part 1 must run first (it deletes the old "CDI Practice" listening test). The
rest can run in any order. Each ~220 KB / ~6,300 lines — comfortably under the
editor limit. (Individual `cambridge<N>-test<M>-listening.sql` files are also
there for one-at-a-time applies.)

## Notes
- Audio is a single continuous recording per test; the player streams it once,
  no pause/rewind, with the four Part tabs for question navigation.
- The map/plan questions display the image above the question; answers are the
  A–J letters marked on it.
